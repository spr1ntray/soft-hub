# Soft Hub

Soft Hub — приложение, в котором удобно держать аккаунты, запускать свои софты и смотреть, что с ними происходит. Всё находится в одном окне: база профилей, настройки, параллельные запуски, прогресс, результаты и безопасные журналы.

Актуальная версия — **Soft Hub 0.6.15**.

## Скачать опубликованную версию

- **[Скачать для Windows 10/11 x64](https://github.com/spr1ntray/soft-hub/releases/download/v0.6.15/Soft-Hub-0.6.15-x64.exe)** — установщик `.exe`;
- **[Скачать для Mac с Apple Silicon](https://github.com/spr1ntray/soft-hub/releases/download/v0.6.15/Soft-Hub-0.6.15-arm64.dmg)** — установщик `.dmg`.

После скачивания запустите файл двойным кликом. На Windows откроется обычный мастер установки; на Mac перетащите **Soft Hub** в **Applications**.

В папке `INSTALLERS` на странице репозитория находится только инструкция — это нормально. Сами крупные установщики хранятся в [GitHub Releases → Assets](https://github.com/spr1ntray/soft-hub/releases/tag/v0.6.15), а ссылки выше скачивают их напрямую.

## Установка

Готовые публичные установщики публикуются в [GitHub Releases](https://github.com/spr1ntray/soft-hub/releases/latest). Для версии `0.6.15` доступны:

- `Soft-Hub-0.6.15-arm64.dmg` — macOS 12+ на Mac с Apple Silicon;
- `Soft-Hub-0.6.15-x64.exe` — Windows 10/11 x64;
- `SHA256SUMS` — контрольные суммы файлов релиза.

Начните с [`INSTALLERS/README_FIRST_RU.md`](INSTALLERS/README_FIRST_RU.md). Python, Node.js, Git, отдельную базу данных и другие служебные программы устанавливать не нужно — всё необходимое уже находится внутри Soft Hub.

Сборки пока не имеют полноценной публичной подписи. macOS может попросить подтвердить запуск в **System Settings → Privacy & Security**, а Windows — показать SmartScreen. Продолжайте только если получили установщик из доверенного источника и сверили SHA-256.

## Что умеет Soft Hub

- хранит профили аккаунтов в зашифрованном Vault;
- принимает приватник, HTTP-прокси, почту, Twitter и AdsPower profile ID одной таблицей;
- хранит общий Capsolver API key и общий AdsPower API key;
- показывает реферальные связи аккаунтов на удобной карте с масштабированием и перемещением;
- устанавливает доверенные софты с диска или из GitHub;
- раскладывает установленные софты по отдельным рабочим разделам **NFT** и **Тестнеты**;
- запускает несколько софтов и несколько аккаунтов параллельно;
- заранее предупреждает, если софту не хватает почты, прокси, AdsPower-профиля или другого ресурса;
- показывает живой прогресс, состояние каждого аккаунта и общий результат запуска;
- собирает Parsing-статистику в таблицу с поиском, фильтрами и выгрузкой CSV;
- скачивает общий очищенный журнал запуска без намеренного вывода приватников и паролей;
- позволяет мягко остановить задачу или принудительно завершить процесс;
- сам проверяет новую версию Hub и скачивает проверенный установщик только после вашего согласия;
- сохраняет историю и результаты после обновления приложения или удаления софта.

## Первый запуск

При первом открытии создайте мастер-пароль длиной не менее 14 символов. Сохраните его в надёжном менеджере паролей: восстановить забытый пароль сейчас нельзя.

Soft Hub просит мастер-пароль при каждом новом запуске приложения. Предыдущая разблокировка не переносится в новую сессию.

Новый Vault пустой. Свежая установка содержит **0 софтов и 0 аккаунтов** — вы сами добавляете только то, чем действительно будете пользоваться.

## Аккаунты

Основной импорт принимает пять колонок:

1. `private_key`;
2. `proxy`;
3. `email`;
4. `twitter`;
5. `adspower_profile`.

Подходит таблица из Excel или Google Sheets, а также CSV/TSV-файл. Строки связываются 1:1: первый приватник получает первый прокси и первую почту, второй — вторые значения и так далее. Если в таблице есть ошибка, Hub не импортирует её частично.

Общий Capsolver key задаётся в **Настройках**. Общий AdsPower API key находится в разделе **Аккаунты**, а AdsPower profile ID указывается отдельно для каждого профиля.

На реферальной карте вы выбираете, какой аккаунт является родителем для другого. Коды конкретного проекта пользователь не вводит: их получает и подставляет сам установленный софт, если он это поддерживает.

## NFT и Тестнеты

В Hub есть три понятных рабочих пространства:

- **Софты** — общая библиотека всех установленных автоматизаций;
- **NFT** — вайтлисты (WL), проверки коллекций, минты и другие действия с NFT;
- **Тестнеты** — парсинг, активности и транзакции в тестовых сетях.

Подходящий раздел задаёт автор патча. Пользователю не нужно раскладывать карточки вручную. NFT-софт для тестовой сети может находиться сразу в двух разделах — это одна установленная копия с общей историей, а не дубликат.

В **NFT** и **Тестнетах** есть свои отфильтрованные карточки, метрики, последние запуски, результаты и Parsing-отчёты. При этом все разделы используют один Vault, одни аккаунты, общий пульт Operations и одну историю: переключение раздела только меняет представление, не выдаёт софту дополнительные данные и само по себе ничего не запускает.

Внутри каждого раздела можно найти софт по названию, описанию или действию, выбрать все готовые карточки и собрать отдельный пакетный запуск только для этого направления. Кнопка **Открыть результаты** переносит тот же фильтр во вкладку результатов; кнопка **Показать все** возвращает общую историю. Пока Vault закрыт, названия и карточки разделов видны, но запуски, результаты и Parsing остаются скрыты.

## Как добавить софт

Откройте **Патчи** и выберите удобный способ:

- перетащите доверенный `.softhub` или `.softhub.zip` с диска;
- вставьте ссылку на готовый пакет в public GitHub Release;
- найдите доступное обновление через Patch Radar.

На странице GitHub Release выбирайте файл `.softhub.zip` именно в блоке **Assets**. Автоматические ссылки **Source code (zip)** и **Download ZIP** содержат исходники, а не готовый патч, поэтому Hub их не устанавливает.

Если браузер переименовал готовый пакет в обычный `.zip` или добавил к имени `(1)`, это не проблема: при локальной установке Hub проверяет содержимое архива и контрольные суммы. Source code ZIP с похожим именем всё равно будет отклонён.

Перед установкой проверьте название, описание, картинку, версию и список нужных доступов. Устанавливайте только свои пакеты или код, которому полностью доверяете.

Обновления софтов идут только вперёд. Понижение версии и откат на старую версию недоступны. На карточке софта остаются две понятные команды: включить или выключить новые запуски и удалить софт.

## Запуск и результаты

Выберите софт, действие и аккаунты. Если софт поддерживает параллельную обработку, задайте число потоков аккаунтов. Для быстрого старта можно отметить несколько карточек галочками и запустить их одной пачкой.

Для NFT особенно важно смотреть не только на название раздела, но и на конкретное действие. Проверка статуса вайтлиста может быть обычным чтением, отправка анкеты меняет внешний сервис, а минт в mainnet, листинг, продажа или подпись ордера OpenSea относятся к mainnet-действиям. Такие действия запускаются отдельно с явным подтверждением и не попадают в быстрый пакетный запуск. Минт в тестовой сети остаётся `testnet_write` и требует подтверждения тестнета.

Во время работы нижний пульт **Operations** показывает активные задачи и те, которым нужно внимание. В подробностях запуска видны общий прогресс, этапы по аккаунтам и полный журнал софта.

Ошибка или принудительная остановка завершают запуск и сразу освобождают аккаунты внутри Hub. Журнал, результаты и история остаются доступны; уведомление можно скрыть после просмотра. Если софт мог успеть отправить транзакцию или изменить внешний сервис, перед повтором всё равно проверьте фактический итог в explorer или API проекта — Hub не может отменить уже отправленное действие.

Во вкладке **Результаты** запуски сгруппированы по софтам. Parsing-действия могут выводить отдельную таблицу статистики по кошелькам: её можно искать, фильтровать и скачивать как CSV.

## Обновление Hub

После запуска Hub проверяет последний стабильный релиз только в публичном репозитории `spr1ntray/soft-hub`. Если приложение остаётся открытым, проверка повторяется раз в шесть часов, когда окно снова активно. Она ничего не скачивает и не отправляет на GitHub аккаунты, ключи или содержимое Vault. Если версия новее, Hub покажет её и сначала попросит разрешение на загрузку.

Новая версия принимается только из защищённого от изменений immutable GitHub Release. Единственное переходное исключение — старый `v0.6.14`: его точный release ID, commit SHA, asset IDs, размеры и SHA-256 заранее закреплены внутри Hub, поэтому заменённый файл также будет отклонён. Для установщика и `SHA256SUMS` обязательны GitHub-computed SHA-256 digests; затем Hub независимо сверяет размер и сам файл до скачивания, после него и непосредственно перед запуском. Открывается установщик только по отдельной команде пользователя и ставится **поверх текущей версии**:

- на macOS Hub откроет проверенный DMG и закроется; перетащите `Soft Hub.app` в **Applications** и подтвердите замену;
- на Windows Hub заблокирует Vault, закроется и запустит проверенный NSIS EXE; пройдите обычный установщик и оставьте прежнюю папку.

Обновление не запустится, пока работают софты. Hub не меняет настройки Gatekeeper или SmartScreen, но конкретное системное предупреждение зависит от версии ОС и метки происхождения файла: отсутствие окна не доказывает, что установщик подписан. Если встроенная проверка недоступна, тот же установщик можно взять вручную в GitHub Releases и сверить с `SHA256SUMS`.

Immutable Release не защищает от захвата самого GitHub-аккаунта и публикации новой вредоносной версии. Поэтому доступ владельца, токены и активные сессии остаются частью цепочки доверия; полноценная публичная доставка дополнительно требует независимой подписи релизного manifest и системных подписей установщиков.

Vault, аккаунты, установленные софты, история и результаты хранятся отдельно от приложения, поэтому обычное обновление их не удаляет. Перед важным обновлением всё равно завершите активные задачи и сделайте резервную копию каталога данных.

## Где лежат данные

```text
macOS:   ~/Library/Application Support/Soft Hub
Windows: %APPDATA%\Soft Hub
```

Не отправляйте этот каталог другим людям и не храните его в открытом облаке. Для полноценной резервной копии закройте Soft Hub и скопируйте весь каталог в зашифрованное хранилище.

## Важно о безопасности

Vault защищает данные на диске, но запущенный софт получает разрешённые ему секреты на время работы. Поэтому:

- используйте только проверенные пакеты;
- начните с тестовых аккаунтов и небольших сумм;
- для тестнетов используйте отдельные пустые кошельки, а не основные аккаунты с активами;
- перед NFT-минтом, листингом или продажей проверьте официальный домен, сеть, адрес контракта, цену, сумму, газ и выдаваемые approvals;
- не отправляйте приватники, пароли и API keys в чаты, issue или скриншоты;
- после принудительной остановки финансового действия проверьте его итог в explorer или самом сервисе;
- перед отправкой скачанного журнала кому-либо просмотрите его вручную.

Подробный пошаговый сценарий находится в [руководстве пользователя](docs/USER_GUIDE_RU.md).
