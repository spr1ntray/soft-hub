# Руководство пользователя Soft Hub

Soft Hub собирает ваши аккаунты, софты, запуски и результаты в одном приложении. Это руководство поможет пройти путь от чистой установки до обычной ежедневной работы.

Актуальная опубликованная версия — **Soft Hub 0.6.18**.

## 1. Что установить

Установщики версии `0.6.18` находятся в GitHub Releases:

| Платформа | Установщик |
|---|---|
| macOS 12+ на Apple Silicon | `Soft-Hub-0.6.18-arm64.dmg` |
| Windows 10/11 x64 | `Soft-Hub-0.6.18-x64.exe` |

Контрольные суммы находятся в `SHA256SUMS` внутри того же GitHub Release. Уже установленная версия Hub сама предложит `0.6.18` в разделе **Настройки → Обновление Hub**.

Больше ничего готовить не нужно. Python, Node.js, Git, Visual C++ Redistributable, терминал и отдельная база данных уже не нужны пользователю Soft Hub.

Intel Mac, Windows ARM и старые версии Windows текущими сборками не поддерживаются.

### macOS

1. Получите DMG из доверенного источника и сверьте SHA-256.
2. Откройте DMG.
3. Перетащите **Soft Hub** в **Applications**.
4. Запустите приложение обычным кликом.

Текущий установщик не notarized Apple. Если macOS блокирует проверенный установщик, используйте штатную кнопку **Open Anyway** в **System Settings → Privacy & Security**. Не отключайте Gatekeeper целиком.

### Windows

1. Получите EXE из доверенного источника и сверьте SHA-256.
2. Запустите установщик.
3. Выберите папку и завершите обычную установку.
4. Откройте **Soft Hub** через Start menu.

Текущий установщик не имеет Authenticode-подписи, поэтому SmartScreen может показать предупреждение. Продолжайте только для проверенного файла и не отключайте SmartScreen глобально.

## 2. Первый запуск и пароль

При первом открытии приложение предложит создать Vault.

1. Придумайте мастер-пароль длиной не менее 14 символов.
2. Не используйте пароль от почты, кошелька или другого сервиса.
3. Сохраните его в надёжном менеджере паролей.

Восстановить забытый мастер-пароль сейчас нельзя.

Soft Hub требует мастер-пароль при каждом новом запуске приложения. Даже если вы разблокировали Vault раньше, следующая сессия снова начнётся с экрана пароля. При блокировке компьютера или переходе в сон Hub также закрывает доступ к чувствительным данным.

Созданный Vault пустой. Свежая установка содержит **0 аккаунтов и 0 софтов**.

## 3. Импорт аккаунтов

Откройте раздел **Аккаунты**. Самый удобный способ — вставить таблицу из Excel или Google Sheets либо загрузить CSV/TSV.

Таблица содержит пять колонок:

1. `private_key` — EVM-приватник;
2. `proxy` — HTTP-прокси;
3. `email` — почта;
4. `twitter` — Twitter-аккаунт, можно оставить пустым;
5. `adspower_profile` — AdsPower profile ID, можно оставить пустым.

Пример прокси:

```text
198.51.100.24:7792:proxy_user:proxy_password
```

Строки соединяются строго 1:1. Первый приватник получает первый прокси и первую почту, второй — вторые значения. Если количество строк не совпадает или значение заполнено неверно, вся операция остановится без частичного импорта.

Повторный импорт того же приватника обновляет его данные, а не создаёт дубликат.

### Общие API keys

- Capsolver API key задаётся только в разделе **Аккаунты**, в блоке **Capsolver API**.
- AdsPower API key задаётся в разделе **Аккаунты**, в блоке **AdsPower Local API**.
- AdsPower profile ID остаётся отдельным для каждого аккаунта.

Других полей для этих ключей в настройках Hub или отдельного софта быть не должно. Если софту нужен Capsolver или AdsPower, он только объявляет ресурс и получает уже сохранённое значение на время запуска. Hub показывает статус ключа и не выводит сохранённое значение обратно на экран. Для браузерного софта сам AdsPower должен быть заранее установлен и запущен.

### Реферальная карта

Нажмите **Настроить цепочку**, чтобы открыть карту аккаунтов. Корни находятся сверху, потомки — ниже, а линии показывают прямые связи.

- нажмите на аккаунт, чтобы увидеть его родителя и ветку;
- выберите нового родителя в панели справа;
- тяните свободное место мышью, чтобы двигать карту;
- используйте колесо или кнопки `−/+` для масштаба;
- нажмите **Показать всё**, чтобы уместить дерево целиком;
- используйте мини-карту для быстрого перехода к большой ветке.

Hub не даст связать аккаунт с самим собой или создать цикл.

Пользователь настраивает только связи между аккаунтами. Реферальный код конкретного проекта получает и подставляет сам софт, если умеет с ним работать.

### Экспорт аккаунтов

Кнопка **Экспорт** создаёт XLSX или raw CSV с основными колонками аккаунтов. Перед выгрузкой нужно повторно ввести мастер-пароль и подтвердить экспорт открытых секретов.

Экспортированный файл больше не защищён Vault. Не открывайте raw CSV в таблицах, если не уверены в его содержимом, и сразу переносите файл в зашифрованное хранилище.

## 4. Установка софта

Откройте раздел **Патчи**. Добавить доверенный софт можно двумя основными способами:

- перетащить `.softhub` или `.softhub.zip` с диска;
- вставить ссылку на готовый пакет в public GitHub Release.

Patch Radar помогает увидеть подходящие пакеты и обновления в GitHub, не перебирая репозитории вручную.

На GitHub нужен файл `.softhub.zip` из блока **Assets**. Не используйте **Source code (zip)** или **Download ZIP**: это архив исходников без служебной сборки Soft Hub.

Браузер Windows может переименовать повторно скачанный файл или оставить ему простое окончание `.zip`. Hub принимает такой файл с компьютера и определяет готовый пакет по безопасной проверке содержимого и контрольных сумм, а не только по имени.

Перед установкой внимательно посмотрите на название, описание, изображение, версию и список данных, которые понадобятся софту. Если происхождение пакета непонятно, не устанавливайте его.

Если после установки появилась команда **Подготовить**, нажмите её и дождитесь завершения. Иногда для этого нужен интернет.

Обновления софта устанавливаются только вперёд. Hub не предлагает более старую версию и не умеет откатывать установленный софт назад. Повторная установка уже активной версии не создаёт дубликат.

На карточке софта есть две управляющие кнопки:

- **питание** — разрешить или запретить новые запуски;
- **корзина** — удалить код и рабочее окружение софта.

Удаление не стирает старые результаты и журналы. Активную задачу сначала нужно завершить.

## 5. Рабочие разделы

Установленные патчи автоматически попадают в один или два рабочих раздела:

- **Софты** — общая библиотека всех установленных автоматизаций;
- **NFT** — вайтлисты (WL), проверки коллекций, минты и другие действия с NFT;
- **Тестнеты** — парсинг, активности и транзакции в тестовых сетях.

Раздел задаёт автор патча. Вручную переносить карточки не нужно. Если один софт относится к NFT и одновременно работает в тестовой сети, он будет виден в обоих местах. Hub не устанавливает вторую копию и не разделяет его историю.

В **NFT** и **Тестнетах** есть свои метрики, отфильтрованные карточки, активные и последние запуски, результаты и Parsing-отчёты. Это только удобные срезы общей истории. Аккаунты, Vault и Operations остаются общими, поэтому можно начать запуск в **NFT**, перейти в **Тестнеты** и продолжить следить за первой задачей через нижний пульт.

У каждого из этих разделов есть собственный поиск по названию, описанию и действиям софта. Кнопка **Выбрать готовые** отмечает только включённые и подготовленные софты текущего раздела, поэтому NFT- и тестнет-пачки можно собирать отдельно. При переходе к пакетному выбору другого раздела предыдущий выбор снимается, чтобы софты из разных направлений случайно не смешались. Перед стартом Hub всё равно покажет выбранные действия, аккаунты и предупреждения — автоматический выбор не запускает их сразу.

Кнопка **Открыть результаты** переводит в общую вкладку **Результаты**, но сохраняет фильтр текущего раздела. Над таблицей будет видно, что показаны только NFT- либо testnet-результаты. Нажмите **Показать все**, чтобы снять фильтр и вернуть общую историю.

Пока Vault закрыт, сами карточки NFT и тестнет-софтов остаются видимыми, но связанные запуски, результаты и Parsing-отчёты скрыты до разблокировки.

Название раздела помогает навести порядок, но не является проверкой безопасности. Перед запуском всё равно посмотрите на действие и предупреждение Hub:

- чтение статуса вайтлиста или баланса ничего не должно менять;
- отправка анкеты, browser submit или регистрация меняют внешний сервис;
- тестовые и mainnet-транзакции запускаются сразу по основной кнопке, без дополнительной фразы или checkbox;
- минт в mainnet, листинг, продажа NFT и подпись ордера OpenSea остаются отдельными mainnet-действиями и не входят в пакетный запуск;
- минт в тестовой сети остаётся testnet-действием и явно обозначается в карточке запуска.

Mainnet-действия не попадают в быстрый пакетный запуск. Запускайте их по одному, после проверки официального домена, сети, адреса контракта, цены, суммы, газа и выдаваемых approvals.

Если нужный раздел пуст, откройте **Патчи** и установите подходящий пакет. Hub не угадывает NFT по названию или картинке: старый NFT-патч без отметки останется только в общей библиотеке, пока автор не обновит пакет. Старые патчи с явно объявленной testnet-транзакцией или testnet-риском Hub может автоматически показать в **Тестнетах**.

## 6. Обычный запуск

1. Откройте **Софты**.
2. Выберите карточку и нужное действие.
3. Отметьте аккаунты.
4. Проверьте параметры.
5. Нажмите **Запустить**.

Если в Vault только один подходящий профиль, Hub выберет его сам. Если профилей нет, из окна запуска можно сразу перейти к импорту.

Перед стартом Hub проверяет нужные данные. Если софту требуется почта, Twitter, AdsPower profile ID, общий API key или реферальный родитель, вы сразу увидите понятное предупреждение. Искать причину в техническом журнале не придётся.

Числовые параметры настраиваются ползунком, а точное значение при желании можно напечатать рядом. Если софт просит диапазон, например от 3 до 8 транзакций, на одной шкале будут два бегунка «От» и «До» — нижняя граница не перескочит через верхнюю.

### Потоки аккаунтов

Поле **Параллельные аккаунты** задаёт, сколько профилей один софт обрабатывает одновременно. Чем больше число, тем выше нагрузка на компьютер, прокси, браузеры и API.

Если появились rate limit, нестабильные прокси или нехватка памяти, уменьшите число потоков.

### Запуск нескольких софтов

1. Отметьте нужные карточки галочками.
2. Нажмите **Запустить выбранные**.
3. Проверьте действия и аккаунты для каждого софта.
4. Подтвердите общий запуск.

Задачи пойдут параллельно, а интерфейс останется доступным. Можно открыть один запуск, затем перейти к другому, не закрывая первый.

## 7. Прогресс и Operations

Нижний пульт **Operations** показывает текущую работу:

- какие задачи запущены;
- сколько аккаунтов уже обработано;
- на каком этапе находится каждый аккаунт;
- какие запуски требуют вашего внимания.

Нажмите строку запуска, чтобы открыть подробности. Сначала показывается понятная таблица состояний по аккаунтам, а полный технический журнал раскрывается отдельно.

Прогресс берётся из этапов, которые сообщает сам софт. Если автор не передаёт промежуточные шаги, шкала может двигаться крупными скачками — это не всегда означает зависание.

Для длинного NFT- или testnet-сценария нормальный прогресс показывает реальные этапы: подготовку аккаунта, вход, проверку условий, отправку действия и подтверждение результата. Полоса, которая долго стоит на нуле, а потом сразу прыгает на 100%, означает, что патч сообщает слишком мало промежуточных состояний. Это не повод считать транзакцию неотправленной: после остановки или ошибки всегда проверяйте внешний результат отдельно.

## 8. Результаты и Parsing

Во вкладке **Результаты** история сгруппирована по софтам. Внутри каждого софта можно выбрать конкретный запуск и посмотреть его итог.

Если действие собирает статистику по кошелькам, результат открывается как Parsing-таблица. Обычно в ней есть:

- аккаунт и публичный адрес;
- итог обработки;
- показатели конкретного проекта;
- поиск и фильтры;
- сводные суммы или средние значения;
- скачивание видимых данных в CSV.

CSV со статистикой не должен содержать приватники и пароли, но может связывать адрес с результатом. Относитесь к нему как к личному рабочему файлу.

NFT-софт может показывать в такой таблице публичный статус вайтлиста, коллекцию, итог минта, количество NFT, token ID, transaction hash или состояние листинга. Testnet-софт — сеть, выполненные задания, публичные transaction hashes, балансы тестовых токенов и накопленные очки. Raw-подписи, signed transactions, приватники, cookies и полный ордер маркетплейса в результат попадать не должны.

Разделы не создают отдельную историю: все запуски по-прежнему собраны в **Результатах** и сгруппированы по софтам. Так один NFT-testnet патч не раздваивается на две независимые записи.

## 9. Журнал запуска

В подробностях можно скачать один общий журнал всего запуска по всем аккаунтам. Hub повторно маскирует известные приватники, прокси, пароли, токены и данные авторизации.

Это дополнительная страховка, а не абсолютная защита. Перед отправкой файла другому человеку всё равно просмотрите его вручную.

### Если запуск завершился с ошибкой

Ошибка завершает запуск и сразу освобождает выбранные аккаунты внутри Hub. Откройте подробности, посмотрите или скачайте общий очищенный журнал и при необходимости нажмите **Скрыть уведомление**. Уведомление исчезнет, а ошибка, результаты и журнал останутся в истории.

Если сбой произошёл после возможной транзакции, browser submit или изменения через внешний API, не спешите повторять действие. Сначала проверьте transaction hash, nonce, order или состояние аккаунта в независимом explorer/API проекта. Hub не требует отдельного подтверждения проверки и не блокирует аккаунты после завершённого запуска, но он также не может доказать, успел ли внешний сервис принять запрос.

## 10. Остановка

Если софт поддерживает аккуратную остановку, нажмите **Попросить остановку**. Hub сразу отправит запрос всему запуску и даст софту короткое время сохранить промежуточное состояние; зависший процесс после этого будет завершён принудительно.

Кнопка **Остановить принудительно** одним нажатием завершает всё локальное дерево задачи. Никакую фразу вводить не нужно. После фактического завершения запуск получает итоговый статус, а его аккаунты освобождаются внутри Hub. Внешнее действие при этом могло успеть выполниться, даже если Hub не получил ответ, поэтому перед повтором всегда проверьте фактический итог.

## 11. Обновление Soft Hub

После запуска Hub проверяет последний стабильный релиз только в публичном репозитории `spr1ntray/soft-hub`. Если приложение работает долго, проверка повторяется раз в шесть часов при активном окне. Во время проверки Hub не отправляет аккаунты, приватники, пароли, прокси, API-ключи или содержимое Vault. Сам установщик без вашего согласия не скачивается.

Версии до `0.6.16` могли показать найденное обновление, но остановить загрузку до первого байта из-за обработки GitHub redirect в Electron. Для них один раз скачайте `0.6.16` вручную из официального Release и установите поверх текущей версии. После этого следующие обновления снова можно скачивать прямо внутри Hub.

1. Завершите активные задачи.
2. В **Настройки → Обновление Hub** посмотрите найденную версию и нажмите **Скачать**, только если хотите обновиться. Загрузку можно отменить.
3. Дождитесь проверки релиза. Hub принимает immutable GitHub Release, требует GitHub-computed SHA-256 для установщика и `SHA256SUMS`, а затем сверяет размер и содержимое файла самостоятельно. Для перехода со старой тестовой сборки отдельно разрешён только точный `v0.6.14`, чьи ID, commit SHA, размеры и SHA-256 заранее встроены в приложение. Любая другая изменяемая, неполная или подменённая публикация не получит кнопку запуска.
4. По возможности сделайте резервную копию каталога данных.
5. Нажмите **Открыть установщик**. Hub ещё раз проверит, что софты не работают, заблокирует Vault и закроется.
6. Завершите установку поверх текущей версии:
   - на macOS откроется проверенный DMG. Перетащите `Soft Hub.app` в **Applications** и выберите **Заменить**;
   - на Windows запустится проверенный NSIS EXE. Пройдите обычный установщик, не меняя прежнюю папку.
7. Снова откройте Hub и проверьте версию, Vault и последние результаты.

Сначала удалять старую версию не нужно. Аккаунты, установленные софты, история и результаты находятся отдельно от приложения и сохраняются при обычном обновлении.

Текущие установщики не имеют полноценной Apple/Windows-подписи. Hub не меняет настройки Gatekeeper или SmartScreen, но наличие конкретного системного предупреждения зависит от версии ОС и метки происхождения файла. Если окна нет, это не доказывает подпись или безопасность установщика. Если автоматическая проверка GitHub временно недоступна, скачайте файл вручную из GitHub Releases и сверьте его с `SHA256SUMS`.

Immutable Release не даёт постороннему заменить уже опубликованные файлы, но не спасает при захвате аккаунта владельца и публикации новой версии. Берегите GitHub-сессию, 2FA, токены и ключи доступа; системная подпись установщика и независимая подпись release manifest остаются следующим обязательным уровнем защиты публичных обновлений.

Обновление самого Hub и обновление установленного софта — разные действия. Новая версия приложения не меняет ваши пакеты без отдельной установки.

## 12. Где хранятся данные

```text
macOS:   ~/Library/Application Support/Soft Hub
Windows: %APPDATA%\Soft Hub
```

Там находятся Vault, база, установленные софты, журналы и результаты. Установочная папка приложения не является хранилищем ваших аккаунтов.

## 13. Резервная копия

Для полной копии:

1. Остановите все задачи.
2. Заблокируйте Vault.
3. Полностью закройте Soft Hub.
4. Скопируйте весь каталог данных в зашифрованное хранилище.

Не копируйте только один файл базы во время работы приложения: часть актуальных данных может находиться во временных файлах рядом с ним.

Экспорт XLSX/CSV не заменяет резервную копию. В нём нет всей истории, настроек, глобальных API keys и реферальной карты.

## 14. Удаление

Чтобы удалить только приложение:

- на macOS переместите **Soft Hub.app** из Applications в Trash;
- на Windows откройте **Settings → Apps → Installed apps → Soft Hub → Uninstall**.

Vault и история останутся на месте для повторной установки.

Чтобы удалить всё без возможности восстановления, сначала закройте Hub, а затем удалите целиком каталог данных из раздела выше. Делайте это только после резервной копии.

## 15. Если что-то не работает

### Приложение просит пароль после перезапуска

Это нормальное поведение. Soft Hub специально требует мастер-пароль в каждой новой сессии.

### Vault открыт, но аккаунтов нет

Разблокировка открывает хранилище, но не создаёт профили. Импортируйте таблицу в разделе **Аккаунты**.

### Софту не хватает данных

Прочитайте предупреждение перед запуском. Добавьте нужную почту, Twitter, AdsPower profile ID или API key в указанном разделе и повторите попытку.

### Модуль просит подготовку

Нажмите **Подготовить** и проверьте интернет. Если ошибка повторяется, сохраните очищенный журнал и передайте его автору софта.

### Софт находится не в том разделе

Раздел приходит из самого патча. Hub не определяет NFT или тестнет по названию, сайту и картинке. Обновите патч, если автор уже исправил его назначение; пользовательского перетаскивания между разделами нет.

### Hub сообщает, что каталог данных занят

Скорее всего, уже открыт другой экземпляр приложения. Переключитесь на него или корректно завершите его. Не удаляйте lock-файл вручную.

### Пароль забыт

Сброса пароля нет. Не удаляйте старый каталог до резервной копии. Для продолжения понадобится чистый Vault и замена всех потерянных credentials.

## 16. Простые правила безопасности

- Используйте только свои или полностью проверенные софты.
- Сначала тестируйте новый пакет на отдельном аккаунте и небольшой сумме.
- Для тестнетов держите отдельные пустые кошельки без mainnet-активов и старых approvals.
- Перед NFT-минтом, листингом или продажей проверяйте официальный домен, chain ID, контракт, цену, `value`, газ и approvals. После сбоя отдельно проверьте transaction hash или ордер OpenSea.
- Не публикуйте Vault, приватники, прокси, пароли и API keys.
- Не считайте список сетей и разрешений полноценной песочницей.
- Помните: во время запуска софт получает разрешённые ему секреты в открытом виде.
- Проверяйте внешний результат после сбоя или принудительной остановки.
- Храните резервную копию в зашифрованном месте.

Soft Hub активно развивается. До использования ценных mainnet-ключей нужен независимый аудит выбранных софтов и понятный план восстановления.
